# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows
[Semantic Versioning](https://semver.org/). While the version is below 1.0.0, minor
releases may change the API.

## 0.1.0 - 2026-11-09

Milestone 1: read, write, validate and inspect. See [docs/roadmap.md](docs/roadmap.md).

### Added

- Parsing and writing of `.gltf` and `.glb`, detected from the content rather than the
  extension. An untouched asset is written back byte for byte, including GLB padding,
  chunks the spec does not define, and every external buffer and image.
- Support for the three ways glTF stores data: the GLB BIN chunk, external files and base64
  data URIs. Relative URIs that are absolute, use backslashes or drive letters, or climb out
  of the asset folder with `..` are refused unless `allowParentPaths` is set.
- `validate()`, with a stable issue code, a JSON Pointer and a plain-English location and
  message for every problem. It checks structure, references, byte ranges, alignment, stride,
  accessor `min` and `max`, index ranges, draw modes, images, samplers, materials, the node
  hierarchy, skins, animations and cameras.
- `inspectAsset()` and `formatReport()`: triangle counts per mesh (stored, instanced, drawn),
  image sizes read from PNG, JPEG and KTX2 headers with an estimated GPU cost, and the byte
  budget of every buffer split into vertex attributes, indices, embedded images, animation,
  skinning, unused bufferViews and gaps.
- `readAccessor()` with support for `byteStride` and padded matrix columns.
- The `forge` command with `inspect` and `validate`, `--json`, and exit codes 0, 1 and 2.
- Hand-written TypeScript types for the glTF 2.0 schema. The package has no runtime
  dependencies (see ADR 0001).
- Procedural fixtures (sphere, torus, textured cube, 50-node scene) generated by
  `scripts/generate-fixtures.mjs`, and a test that fails if they drift from the generator.

### Known limits

- Accessors are read into memory whole; sparse accessors and compressed geometry are not read.
- A `.gltf` cannot be converted to a `.glb` yet.
- Nothing is optimized yet. Decimation, texture processing, LODs and size budgets are
  milestones 2 to 5.
